# 移动端精简入口页改造方案

## 概述

将 `index.html` 移动端（≤768px）从"一页式长滚动"改为"精简入口页"：
- 移动端只保留：主KV图 → 展会概览（时间地点+核心数据）→ 六大主题展区 → 快捷入口卡片 → 精简页脚
- 原长页中的"展会日程、同期论坛、参展品牌、展会资讯、参展指南"五大版块在移动端隐藏，通过快捷入口卡片跳转到已有的独立子页
- 桌面端（>768px）保持现有布局完全不变

## 现状分析

- [index.html](file:///d:/WorkFile/zhanltWebsite/index.html) 为单页长滚动结构：hero → highlights(六大展区) → schedule(日程) → forum(论坛) → brands(品牌) → news(资讯) → guide(指南) → footer
- 各版块均有独立子页：schedule.html / brands.html / news.html / guide.html / register.html / cooperation.html / recruit.html
- [style.css](file:///d:/WorkFile/zhanltWebsite/style.css) 已有 1200/992/768/576 四档响应式断点，移动端为单列布局
- 多语言数据内嵌在 [i18n.js](file:///d:/WorkFile/zhanltWebsite/i18n.js) 的 `LANG_DATA['zh-CN'|'zh-TW'|'en']` 三块中，可复用键：`hero.stat*.value/label`（展会数据）、`nav.*`（导航标题）、`guide.card1.desc`（场馆名）、`guide.card2.desc1`（展会时间）
- [main.js](file:///d:/WorkFile/zhanltWebsite/main.js) 的 `updateHeroStats()` 会按 DOM 顺序更新所有 `.hero-stat-value`，移动端数据条复用该类即可同步后端数据

## 方案设计

### 1. index.html — 新增两个移动端专属区块

**A. 展会概览条 `.mobile-overview`**（插在 hero 区块 `</section>` 之后、`#highlights` 之前）
- 结构：标题（新键 `mobile.overview.title`）+ 时间/地点行（复用 `guide.card2.desc1`、`guide.card1.desc`）+ 2×2 数据格（复用 `hero.stat1~4` 的 value/label，类名沿用 `hero-stat-value` / `hero-stat-label`，保证 `updateHeroStats()` 生效）
- 标注 `data-i18n` 属性；时间/地点用 `data-i18n` 指向现有 guide 键

**B. 快捷入口区 `.mobile-quick-links`**（插在 `#highlights` 区块 `</section>` 之后、`#schedule` 之前）
- 标题：新键 `mobile.quick.title`
- 6 张入口卡片（图标 + 标题 + 箭头），标题复用 `nav.*` 键：
  1. 展会日程 → schedule.html（icon: fa-calendar-alt）
  2. 参展品牌 → brands.html（icon: fa-award）
  3. 展会资讯 → news.html（icon: fa-newspaper）
  4. 参展指南 → guide.html（icon: fa-map-signs）
  5. 观展预约 → register.html（icon: fa-ticket-alt）
  6. 人员招募 → recruit.html（icon: fa-users）
- 所有卡片为 `<a>`，移动端点击直接跳转子页

### 2. style.css — 基础规则 + 移动端断点规则

**基础样式（全局，桌面端也加载但隐藏）：**
- `.mobile-overview, .mobile-quick-links { display: none; }`

**≤768px 媒体查询内新增/覆盖：**
- 显示新区块：`.mobile-overview, .mobile-quick-links { display: block; }`
- 隐藏五大长页版块：`#schedule, #forum, #brands, #news, #guide { display: none; }`
- `#highlights` 压缩：
  - `.highlight-cards { grid-template-columns: repeat(2, 1fr); }`（原单列改为两列，高度减半）
  - `.highlight-card { padding: 18px 14px; }` 并缩小 `.highlight-icon` / `.highlight-title` / `.highlight-description` 字号（标题超长自动换行，无需截断）
- `.mobile-overview` 样式：居中布局，时间/地点行 + 2×2 数据格（`.mobile-stats`，grid 2 列，数值用品牌渐变/玫红色，字号 1.4rem 左右）
- `.mobile-quick-links` 样式：`.mobile-quick-grid { grid-template-columns: repeat(2, 1fr); gap: 14px; }`，卡片为圆角白底卡片（边框/阴影沿用品牌 token），图标+文字居中，整卡可点
- 页脚精简：`≤768px` 下 `.footer-links { display: none; }`，保留 footer-brand（简介+联系方式）、footer-organizers、footer-bottom
- 原 `.highlight-cards { grid-template-columns: 1fr; }`（现约 2471 行）改为 2 列规则覆盖

### 3. i18n.js — 新增 2 组键（三种语言各一）

在 `LANG_DATA['zh-CN']`、`LANG_DATA['zh-TW']`、`LANG_DATA['en']` 三块中新增：
- `mobile.overview.title`：展会概览 / 展會概覽 / Expo Overview
- `mobile.quick.title`：快速入口 / 快速入口 / Quick Access

（入口卡片标题、数据、时间地点全部复用现有键，避免大范围新增翻译）

### 4. 不改动的部分

- main.js：无需改动（`loadPageData()` 对隐藏容器渲染无害；`updateHeroStats()` 自动同步移动端数据条）
- 其他子页面、桌面端布局、导航菜单逻辑均不动

## 假设与决策

- "短页面" = 移动端首页精简为入口页，已与用户确认；桌面端保持不变，已与用户确认
- 移动端保留六大主题展区（用户确认项），但改为两列压缩展示以控制高度
- 隐藏的五大版块内容全部由快捷入口卡片承接，导航栏汉堡菜单仍可直达各页
- 页脚在移动端隐藏三列链接，保留品牌简介、联系方式、主办协办承办单位与版权

3. 确认无大片空白，KV 底与概览条衔接自然

5. 切换简/繁/英三种语言，确认新增标题与数据文案正常翻译
6. 桌面端视口（1280px+）打开首页，确认原长页布局与各版块完整显示，两个新移动端区块不出现
